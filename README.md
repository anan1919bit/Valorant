# 无畏契约单机 AI 自瞄｜VisionHID v0.4.1

面向本地训练场景的 Windows 视觉目标检测与 ESP32-S3 USB HID 鼠标控制实验。识别亮黄色人形目标，以身体框维持目标身份，并在头部、身体和混合瞄点间切换。V0.4.1 增加模型下载与一键安装；瞄准算法和原有参数保持 V0.4 基线。

项目背景与技术栈见 [项目介绍.md](项目介绍.md)；模型结构与准度设计见 [MODEL.md](MODEL.md)。

## 一键安装

在 Windows 安装 Python 3.12 后，克隆仓库或下载本版本源码包，双击 `一键安装.cmd`。脚本创建 `.venv`、安装固定版本依赖、从 [v0.4.1 发布页](https://github.com/anan1919bit/VisionHID/releases/tag/v0.4.1)下载模型、核验 SHA-256，并生成个人 `config.ini`。已有配置不会被覆盖。使用自己的 AI 编程工具安装时，复制 [AI_INSTALL.md](AI_INSTALL.md) 中的提示词即可。

安装脚本不自动烧录 ESP32，也不自动配置 CUDA/cuDNN。运行前在 `config.ini` 中填写当前串口；留空时仅检测、不发送 HID 移动。

## V0.4 变化

- 使用稀疏背景光流估计镜头移动，从目标框位移中扣除这部分共同运动，改善单目标横移时的提前量。只在已锁定的小/中目标附近运行；无可靠光流时沿用原估计。
- 目标真实检测短暂中断时，仅对此前已确认的同一 track 做最多 2 帧、总年龄不超过 75 ms 的预测接续；预测帧每轴最多 8 HID count，绝不用于点击。超时、换目标或失焦立即停止。
- `config.ini` 的 `motion_compensation` 与 `prediction_bridge` 可分别设为 `yes/no` 做 A/B 对照；修改后重新启动。默认均为 `yes`。
- `--video <文件> --simulate-control --max-frames 420 --headless` 可离线回放瞄准决策，始终不连接串口。

对用户提供的 420 帧录像做模拟控制回放：关闭两项功能时 real=397、bridge=0、gated=23；开启后 real=397、bridge=15、gated=8。背景光流在该视频上预热后 p95 约 2.3 ms。此验证不代表游戏实时命中率或帧率提升。

## V0.3 变化

- 已锁定的中远距离小目标：每 5 帧回全图刷新，其余帧使用 256×256 局部裁剪并映射回全图坐标；仍按真实 YOLO 框驱动。
- 全图漏检后，黄色哨兵改为隔帧检查；前三个黄色候选轮换，每帧只裁剪推理一个。已经锁定时优先复检锁定附近候选。
- 裁剪帧跳过无用的全图缩放预处理；默认 `secondary_inference=no`，避免同帧重复推理。
- `--image` 离线回放保留跟踪状态以验证连续局部放大，但从不发送 HID 命令。

黄色候选不是另一个训练模型；补漏使用的是同一个 ONNX 模型的放大裁剪推理。已有远景截图的 8 帧回放确认局部放大分支能检出目标，实时游戏效果仍需单独测试。

## V0.2 变化

- 全图 YOLO 对同时具有匹配真实头框的远距离小身体框启用原有 tiny 规则；不再统一以 24 像素高度挡掉。
- 提前量上限随目标框宽度缩小，降低远处小头框被预测点跨过的风险。
- `tools/benchmark_far.py` 可对本地截图打印全图、筛选和颜色裁剪结果。

两张已有远景截图的离线复测中，全图模型都输出了真实身体与头框，但旧尺寸规则均未放行；V0.2 的头框确认规则均放行。其中一张单帧主程序回放由 `targets=0` 变为 `targets=1`。这不是游戏实时命中率证明。

## 当前能力

- dxcam 截取屏幕中央 960×960，ONNX Runtime GPU 推理 640×640 的 ONNX 模型；模型输出 5 类，程序只读取类别 0（身体）和 1（头部），分别做 NMS 后选择目标。
- 跟踪同一目标；真实检测框正常驱动，短暂漏检时仅对已确认目标做最多两帧的限幅预测移动，预测框不用于点击。
- 蹲姿瞄点修正、动态提前量、黄色高亮候选裁剪复检、头/身混合模式、半透明状态悬浮条和参数 UI。
- ESP32-S3 接收 `M,dx,dy\n` 相对移动；固件也实现 `P\n` 和 `C\n`，但本版本默认不自动点击。
- 运行控制：F5 头身混合；F6 头/身切换；F9 关闭；F10 退出；F11 开关；F12 调参。

## 快速开始

1. 在 Windows 安装 Python 3.12，双击 `一键安装.cmd`；GPU 推理仍需可用的 CUDA/cuDNN 环境。
2. 脚本自动下载经过 SHA-256 核验的模型到 `models`。预期输入 `[1,3,640,640]`、输出 `[1,9,8400]`；程序仅使用类别 0/1。
3. 双击 `启动 VisionHID.cmd`。在 `config.ini` 中将 `device.port` 填为当前 ESP32 串口（例如 `COM4`）；留空则只运行检测，不输出 HID 移动。
4. `config.ini` 的 `device.window_title` 留空时不检查前台窗口标题；填入标题时才要求精确匹配。当前本机配置已留空，但源码包示例仍是 `VALORANT`。`aim_calib.json` 缺失时使用检测区中心，个人校准文件不进入源码包。
5. 运行日志在 `run.log` / `error.log`。运行前关闭原 V4/V5 进程，避免同时占用串口和 GPU。

## 结构

- `src/visionhid.py`：采集、YOLO 推理和主循环。
- `src/box_tracker.py`、`src/person_aim.py`、`src/target_policy.py`：跟踪、控制和目标筛选。
- `src/yellow_proposals.py`：黄色候选与裁剪复检。
- `src/motion_predictor.py`：背景运动补偿与短时预测接续。
- `src/v4_tuning_ui.py`、`src/status_overlay.py`：参数窗口与状态条。
- `firmware/aimlab_hid_bridge.ino`：ESP32-S3 串口到 USB HID 桥接。

## 验证与已知问题

`py -3.12 -m unittest discover -s src -p "test_*.py"` 运行离线测试。当前分发版仍需在不同电脑、模型、串口和游戏设置上实测。中远距离的小目标仍可能漏检，颜色哨兵也可能提出未被模型确认的候选；降低置信度不一定能解决这些情况。
